      BReference & metadata

      Reference

      Segmented virus. Your BAMs hold one sequence per segment. The reference must contain every segment, and every BAM must have the same segments.

      • GenBank file(s): one file per segment, or one file with all the records.
      • FASTA and gene list: one FASTA and one gene list per segment (or one of each with all the segments); this page joins them in the order of the lists.
      • The other ways (own consensus, NCBI accessions) are available in srasel run and srasel web, one source per segment.

      Keep the same order as the BAM header (samtools view -H sample.bam | grep '^@SQ') and the same order every time: the order only changes the internal numbering of positions and, slightly, the permutation p-values.

      Choose GenBank file(s)

        The annotated record(s) the reads were aligned to. Choosing again adds files to the list. For a segmented virus, turn on “Segmented virus” above.

        One file per segment (or one file with every segment), in the order of the BAM header. Choosing again adds files to the list; use the arrows to reorder them.

        Sequence (FASTA)
        Choose FASTA

          The sequence your BAMs were aligned to (.fa, .fasta, .fna, .fas).

          Gene list
          Choose gene list

            A tab-separated table with a header (.tsv, .txt), or a GFF3 (.gff, .gff3).

            Sequences (FASTA): one file per segment, or one with all
            Choose FASTA file(s)

              Every sequence needs its own name, the same one your BAMs use. The files are joined in the order of this list. Choosing again adds files.

              Gene lists: one file per segment, or one with all
              Choose gene list(s)

                Tables (.tsv, .txt) or GFF3 files, all in the same format. The contig column says which segment each gene is in. The columns may differ between files. Choosing again adds files.

                Format

                One row per gene, columns separated by tabs, first row is the header:

                contig  gene  start  end  strand  [type]  [product]  [codon_start]  [transl_table]
                • contig: the sequence name, as in the FASTA and in your BAMs.
                • start, end: 1-based positions, both inclusive (start < end).
                • strand: + or -.
                • Optional columns, found by their header name: type CDS (default) or mat_peptide; product; codon_start 1, 2 or 3 (default 1); transl_table genetic code (default 1).
                • A gene in several pieces: several rows with the same contig and gene.
                • Segmented virus: the contig column names the segment of each gene.

                Notes
                
                    
                  
                  • Experimental: it can be slower than the command line and can fail on browser memory limits. For routine work use the command line or the local web interface.
                    • 
                  
                  • BAM files must be coordinate-sorted (no index needed); a folder uses every .bam inside; tables ending in .gz are decompressed here; NCBI download is not available.
                    • 
                  
                  • BAM files are counted here with pysam, using the same rules as bam-readcount -q 20 -b 20 -w 0 (identical counts on the 47 real BAMs tested; see BAM_COUNTER.md), and are read in place, never uploaded. Tables from srasel run or bam-readcount are faster.
                    • 
                  
                  • Some options of srasel run are not offered here; the full table is in docs/WEB.md.
                    
                    
                      Not available in the browser
                      
                      
                        
                    • --virus, --ref, --email: no NCBI download here; load the GenBank file (or a FASTA and a gene list), or use the command line or the local interface.
                      • 
                        
                    • --consensus, --consensus-source: transferring genes needs minimap2; load the annotated consensus (consensus_annotated.gb) as the GenBank file, or give a FASTA and a gene list.
                      • 
                        
                    • --samples, --fragments: name the files <patient>-<n> or add a patient column to the dates file; one BAM per fragment needs the command line or the local interface.
                      • 
                        
                    • --check-only: the checks use samtools; use the command line or the local interface (Check inputs).
                      • 
                        
                    • --threads: one process in the browser; the results do not depend on it.
                      • 
                        
                    • --resume, --out, --yes: nothing is kept between runs in a tab, results come as a zip, and nothing is asked.
                      • 
                      
                    
                    
                    • 
                  
                  • The first load needs internet to fetch the runtime (Pyodide …) from cdn.jsdelivr.net; a second analysis in the same tab works offline. Closing the tab discards everything, so download your results first.
                    •

                        About browser mode
                        
  
                        
    
                        SRASel looks for directional frequency changes of viral variants across several samples of the same patient over time. Browser mode runs the same scientific engine as the command line, in Python compiled to WebAssembly (Pyodide), inside this tab. Nothing is uploaded: the only download is the Python runtime, from cdn.jsdelivr.net.
